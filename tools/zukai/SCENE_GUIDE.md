# 図解ショートのシーンJSONの書き方（ミケの図解）

縦 1080×1920、50〜65秒。**1枚の図が最初から最後まで画面に残り、ナレーション1文ごとに少しずつ育っていく**動画を、JSONだけで書く。
動き（出現・移動・数値のカウント・色の変化・線が伸びる）はエンジンが補間する。座標と「いつ・何を・どう変えるか」だけを書く。

## 1. 台本の型（ステップ＝ナレーション1〜2文）

| # | 役割 | 見出しの例 | 画面 |
|---|---|---|---|
| 0 | 問い（フック） | `CDNで\nなぜ速くなる？` | **完成図を一瞬見せる**（最初のフレームがサムネになる）。ミケは detective |
| 1 | 場面 | `遠いと往復に時間がかかる` | 完成図を消して、登場人物（箱）だけにする |
| 2〜3 | 素朴なやり方と限界 | `1往復 約150ms` | 実際の値で動かす（カウンター、点の往復） |
| 4 | 鍵になる発想 | `近くにコピーを置く` | 新しい部品が登場する |
| 5〜6 | 同じ場面で効果を確かめる | `1往復 約10ms` | 比べる（バーを並べる、色で勝ち負け） |
| 7 | まとめ | `距離を縮めて\n待ち時間を減らす` | 図全体のうち大事な所を青く光らせる |
| 8 | 解説動画へ（cta） | `続きは\n4分の解説で` | `"cta": true`。図は自動で薄くなり、ミケが大きく出る |

- 1本で問いは1つ。題材は「名前は知っているが、仕組みを人に説明できないもの」。
- **具体的な値を必ず出す**（`5^6 mod 23 = 8`、`150ms`、`E3 81 82`、実際のコマンドや設定名）。数字は出典で確かめたものだけ。
- 見出しは「言い切りの1文」で、全角14字以内×2行まで（ステップ0とctaは10字×3行まで）。名詞だけの見出し（「仕組み」「ポイント」）は使わない。
- ナレーションは1ステップ1〜2文、合計で50〜65秒になるようにする（1ステップ3〜6秒）。英字はカタカナ読みで書く（シーディーエヌ）。
- 字幕は出さない。画面に出る文字は見出しと図の中の短い言葉だけ。

## 2. 画面の決まり

- 表示範囲：x 40〜1040、y 470〜1860（上は見出し、下は余白）。
- **右下（x>690 かつ y>1430）はミケの場所**。そこに部品を置かない。
- 横の位置の目安：左 x=200、中央 x=540、右 x=880（箱の幅 300〜320 のとき）。
- 縦の位置の目安：y=640, 800, 960, 1120, 1280, 1400（箱の高さ 150〜160 のとき、隣の行とは 160 以上あける）。
- 色の意味は固定：**blue＝いま注目している所・正解**、**green＝成功・正常**、**red＝失敗・異常・遅い**、**yellow＝動いているデータ**、gray＝その他。

## 3. 部品（nodes）

座標 x, y は中心（bar だけ x は左端）。全部の部品に共通：`opacity`（最初は0＝非表示）、`scale`、`color`、`dim`（0〜1。1で薄く暗くなる）。

| type | 主なプロパティ | 用途 |
|---|---|---|
| `box` | w, h, label（全角6字まで）, sub（全角9字まで） | 登場人物・サーバー・状態 |
| `chip` | text（半角14字まで）, size（既定34） | ラベル、ファイル、データの粒、結果の札 |
| `counter` | value, decimals, prefix, suffix, size（既定96）, caption | 数が増える・減る（回数、時間、件数） |
| `bar` | w（長さ。最大650）, label, text | 量を比べる |
| `line` | x1,y1,x2,y2, draw（0→1で伸びる）, dashed, text | つながり・通信路・距離 |
| `dot` | r | 線の上を動くデータ（重なり判定の対象外） |
| `text` | text, size, weight | 補足の1行（多用しない） |
| `code` | lines（配列、半角40字・5行まで）, size（既定38）, w, hl（光らせる行番号。-1でなし） | コマンド・設定ファイル・ログ |

## 4. 動き（steps[].keys）

```json
{"at": 0.3, "dur": 1.1, "ease": "inOut", "show": ["pk"], "hide": ["h1"], "set": {"pk": {"x": 720}, "c1": {"value": 150}}}
```
- `at`：ステップ開始からの秒。`dur`：かける秒数（既定0.4、0で即時）。`ease`：inOut（既定）/ out / linear（カウンターは linear が自然）。
- `show`：ふわっと出す。`hide`：消す。`set`：数値・色・文字を変える（数値と色は補間、文字はその瞬間に切り替え）。
- よく使う動き：
  - 点の往復：`set pk.x` を行き・帰りの2つの key で。
  - カウンターと連動：点が動いている間に `set c1.value` を linear で同じ長さ。
  - 線が伸びる：`set ln.draw: 1`（dur 0.6〜1.2）。
  - 注目：`set box.color: "blue"`、ほかを `dim: 0.6`。
  - 分岐の結果：選ばれた側を green/red に、選ばれなかった側を `dim`。
  - コード：`set code.hl: 2` で3行目を光らせる。
- ステップ0では `dur: 0` で完成図を出し、ステップ1の最初の key で `hide` して作り直す。
- 1ステップの key は `at+dur` がそのステップの長さ（ナレーションの長さ＋0.35秒）に収まるようにする（目安3秒以内）。

## 5. ミケ（steps[].mike）

`public/mike/` にある画像名（`<表情>_open.png` / `<表情>_close.png`）の表情名を書く。口は声に合わせて自動で動く。
問い・発見・考えるときは detective、説明は talk など、内容に合わせて選ぶ。

## 6. meta（タイトル・概要欄）

```json
"meta": {"title": "CDNとは？速くなる仕組みを60秒で", "intro": "概要欄の1行目",
         "hashtags": "#テック朝刊 #CDN #Web", "kaisetsu": {"kind": "解説", "title": "解説動画のタイトル", "minutes": 4}}
```

## 7. 作る手順とチェック

1. `LINT_ONLY=1 python3 build.py scene.json out` … 音声の長さと配置チェック（はみ出し・重なり・ミケとの重なり・見出しの長さ）。ERROR が0になるまで座標を直す。
2. `python3 build.py scene.json out` … 動画を書き出す（約2分）。
3. `out/check.png`（全ステップの終わりの画面を並べたもの）と `out/short_frames/v00.png`（サムネ）を目で見て、読みにくい所・意味の通らない図がないか確かめる。
4. 長さが50〜65秒から外れたら、ナレーションの量で調整する。
